<architecture>
    One LWSE server per node with three ports (DESIGN.md 10.2): the mesh port (bound, or a number in memory) Through(MeshTls server).Speak(AMP/1); Ports.Outbound, adopt-only, Through(MeshTls client).Speak(AMP/1) for every dial; Ports.Local, adopt-only, Speak(axiom-mesh-local/1). ServerOptions.Admission.PerClient = 4. NodeModule registers the protocols, the transport, the observer and four LoopServices (dialler, discovery, trust, evictor) that wait until the ports are bound. MeshTls: TLS 1.3, client certificate required, AllowTlsResume false, no renegotiation, no chain or revocation check, a 10 s handshake deadline on the node clock; PeerCheck accepts in the callback only a key TrustSnapshot.TryResolveDevice resolves (or, while a pairing waits, a pairing candidate), and Decide after the handshake admits a roster key under axiom-mesh/1 and a pairing key under axiom-mesh-pair/1 only. PeerSessionHandler writes its Hello first, checks the peer's with HelloRule.Check against one snapshot, applies the duplicate rule through PeerTable.Establish (the loser hears Bye(Duplicate)), sends the Roster follow-up, then hands the session to a ReplicationSession until it ends, is asked to close (Duplicate, Unauthorized), breaks a rule (Bye(Violation)) or the node drains (Bye(Shutdown)). Replication: the push loop sends the listing (exactly the followed Packages TrustSnapshot.MayList allows, 64 per page) on establishment and whenever the listable set changes, PackageChanged and Have for each committed ChangeSet to every session but the change's origin, the revocation Grant to the revoked user, and the own Roster when its seq rises; the read loop runs ListingRule, plans with ReplicationPlanner into the WantScheduler, answers Want after ServedObjects (Promises.Protect while queued, PinCommand Sent after), takes Objects through Intake (the want stays until the store decided), answers RosterQuery under 9.8, and records violations and faulty content; the write loop reads stored objects into a pooled buffer and sends them with ObjectMessage.FromStored. The store writer keeps HeadsView and the links of every stored object (StoredObject.Links) for the walk, refuses an Entry whose held parents fail Lamport.TryFindParentFault (AdmitOutcome.Faulty), and keeps an own Grant an owner's listing withdrew (WithdrawGrantCommand) as rights None. LinkActivity counts bytes and times every frame from its first byte (30 s). PeerTable (one lock, no I/O inside, an immutable view, facts recorded after the lock) is fed by DiscoveryPump (announcements; after a trust change it closes untrusted sessions and offers CompositeDiscovery.Cache.Snapshot()), by PeerDialler (TryReserve, IDialer.DialAsync, AdoptAsync, DialEnded) and by sessions; a backoff schedules a retry timer that re-offers the device at its last address. One writer, immutable snapshots, per-session actors (plan decision D8), as in M5. The local port (M8): LocalPort.AdoptAsync gives every connection its own 127.x.y.z remote (admission counts per address) and records its ProcessIdentity and LinkActivity for LocalPortHandler; LocalConnection reads Hello, decides it with ConnectionBook.Admit (LocalHelloRule in the order of LOCAL-SPEC 4.2, registration in the same lock), writes HelloAck (identity, store epoch and seq, capability bit 1 for another OS user), then dispatches each RequestFrame through DispatchRule (role, NoIdentity, Draining, user-key confinement and the log line, then the handler or UnknownRequest), ordered requests (all but Get*/List*) through one lane per connection; every answer goes to the Outbox control lane, written before events; a subscription's events are written only after its Subscribe response, a replay reads one Entry per step (EntryRecords.EventAtAsync), Offer lapses a subscription at 256 events or 16 MiB and reports Overflow past 64 MiB per connection (the port closes the heaviest connection past 256 MiB); operations announce their first event after the starting response. LocalEventHub turns ChangeSets (one ChangeBus subscription of 1 024) and PeerTable views into events once each. MeshNode.StopAsync drains the port (Drain, the grace, Bye(Shutdown)) before the server. Requests (M9): a handler checks substance with a pure rule (RequestRefusal -> the status of LOCAL-SPEC 11.1), then sends store commands and answers once they committed; user-key requests sign inside MeshNode.WithUserKeyAsync. Fetch and Materialise run as operations over ObjectFetcher: Fetch wants (WantKind.Fetch) sourced by the sessions that list the Package, a change subscription settles them, a look each second on the node clock decides the 60-second no-source failure; cancel calls WantScheduler.CancelFetch. WriteEntry goes through the CredentialSlot's EntryWriter; references of extension kinds travel in AdmitCommand.References so the writer pins them Outbound and Policy.
</architecture>

<best_practices>
    Start a node only through MeshNode.StartAsync with every seam in MeshNodeEnvironment; trust enters only by AdoptIdentityAsync and AcceptUserAsync, which the pairing shell calls once a pairing is Paired. Read trust through the writer's current snapshot, never a ChangeSet's (it may be stale when read). Decide with the pure rules (DialPolicy, Backoff, ViolationWindow, DuplicateSessions, HelloRule) and keep the table's lock free of I/O and waiting. Record a NodeFact for every decision about a connection or a peer, after the state it reports is published. Store only through AdmitCommand with a StorableObject; for objects from peers go through Intake. Every limit comes from Model's Limits. Keep the planner and listings pure; the session only sequences. Check visibility on every listing, Have, Want answer and Roster; send stored bytes only from the session's send path (SendPathTests). Settle a want only once the store decided, so no plan wants it again meanwhile. Tests wait with TestNode.WaitForObjectAsync and TestMesh.SettleAsync, which read MeshNode.Replication.
</best_practices>

<pitfalls>
    On .NET 8 (Windows) the certificate callback cannot read the negotiated ALPN; PeerCheck.Decide after the handshake is the authority (STRUCTURAL-DEBT 21). A pairing-ALPN connection reaches the AMP/1 handler, which hands it to PairingShell.ServeAsync: AMP/1's Connected state is switchable, and the shell switches the untouched session to PairProtocol.Definition with ProtoStream's SwitchAsync (no final message; debt 22 paid); with no pairing running it is aborted without a byte. The pairing shell takes every event under one SemaphoreSlim and never holds it while reading; it stores results before it sends the frame that completes the pairing; the showing side closes once Paired, the entering side waits for that close, then dials the shown device (PeerTable.DialPaired). Local clients die if a test advances the fake clock past their 120 s idle backstop: advance in steps and send a request in between. SslStream on Windows reports LocalCertificate and the client side's IsMutuallyAuthenticated unreliably with ClientCertificateContext; do not decide on them. Two sessions to one device exist for a moment while the duplicate rule closes one: the scheduler addresses the one attached last and re-asks what the closed one carried; an object may then arrive twice (harmless). The write loop is not awaited when a session ends (a blocked write ends with the connection). ObjectMessage.FromStored trusts its caller: never call it outside ReplicationSession. A parsed object refers to the memory it was parsed from: copy a frame before parsing. LDB 0.1.0 has one [Key] per entity: multi-part keys are concatenated (RowKeys). Core and Local both define PinReason, PackageState, PeerState and StoredObject: alias the Local one in files that import both. A ChunkStreamer Chunk lives in a pooled buffer until its sink returns: store it (the writer copies) before returning. A local request never waits on a peer: anything that may take long is an operation.
</pitfalls>
