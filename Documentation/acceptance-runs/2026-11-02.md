## What the run found

1. **Stale service identity (bug, fix before v0.2.0).** A service takes its own identity from the Host's `HelloAck` when
   it connects. A's chat and sync services were spawned at Host start, before `identity create`, and kept an empty
   identity: the Channel owner's own device got `NotYours` on `chat withdraw`; after the service was restarted the same
   command succeeded (redaction 6254d6cf8875). The sync service reads its own device id the same way (`SyncRun.Own`,
   `Publisher`); it was restarted before step 12. The runtime must refresh the identity when it changes, or read it
   before each decision.
2. **Firewall.** A Host started by the logon task shows no Windows firewall prompt, so on A (Public network profile)
   inbound TCP 41810 stayed blocked; B's port was open. Everything worked with A dialling B, but B's `pair join` into A
   hung for minutes (debt 85), step 7 took 71 s, and Eve had to be dialled from A. The install needs an inbound rule
   for `axiom-meshd.exe` (administrator) or clear guidance; a peer's fresh discovery announcement should reset the dial
   backoff.
3. **Pairing code.** 340 characters with every interface address; nobody types that. Pairing by discovery (commit
   e180e0a, PAIR-SPEC draft 3) is the answer and was not in the binaries under test. A join that reaches no address
   holds the Host "busy" until every address timed out or the pairing expires.
4. **Defender** flagged the unsigned command line once (debt 79); the rebuilt zip and PC B were not flagged.
5. **Document and command inconsistencies:** step 11 needs the write grant step 9 revokes (re-granting also delivers the
   post-revocation Entry, correct per SPEC §9.7); `package materialise` refuses an existing empty folder while `sync
   add` refuses a missing one; `package list` on B showed rights `none` before the follow although read grants
   existed; after a merge both PCs wrote an identical merge Version within the same second (two leaves with one tree
   until the next change, debt 83); a conflict row stays listed after its copy was deleted (debt 84).
6. **Timings:** first sync of 3 files 1.7 MiB on B 1 s; B's edits on A within 3 s; merge after reconnect within 20 s;
   40 × 1 MiB on B 7 s after A's Version; chat attachment 293 KiB fetched at once; service restarts 1–6 s.
7. **CI (first runs ever, on the push of 2026-11-02):** build against the published LDB 0.1.0 (3dcab92), the workflow
   parse error, pack with `--no-build`, the Linux allocation bound, PowerShell 7 for the scripts (f4a2cc8). Still red
   after that: `tls-scan` reports a TLS session ticket issued on Linux (SPEC §4.2 forbids them, debt 86); `unit-tests`
   on windows-latest failed `ServiceSpawnTests…IsRestartedAfterItWasKilled` once with "The connection to the Host
   ended: a request could not be written … The flush was cancelled" on the test's user connection (Linux green; the
   cancelled-flush family of debt 53 and 78).
